# المرحلة الثالثة — فحص قبول التقرير التنفيذي لمنصة IAU-DEEDS

## 1. نطاق التنفيذ المحقق
- فحوصات GitHub Action لنسخة الواجهة: `npm run build`، و`npm run test:ui:contracts`، و`npm run test:ui:browser`.
- سيناريوهات متصفح ببيانات اصطناعية فقط: حساب مسؤول، وحساب موظف بصلاحيات مبانٍ فقط، وحساب بلا صلاحية تقارير، وفشل أحد المصادر، وتصدير Excel والفحص البرمجي لأوراقه، وطباعة ملف PDF بواسطة Chromium.
- التحقق من صلاحية `reports.canView` لفتح الصفحة، وصلاحية `reports.canPrint` للتصدير والطباعة.
- في `Root.tsx` لا تجري صفحة التقرير التنفيذي التحميل الشامل المسبق لجميع الأصول؛ كل مصدر يُقرأ عند الحاجة فقط وبحسب صلاحية الوحدة.
- لا تُرسل أي طلبات في الاختبارات إلى Railway أو قواعد بيانات الجامعة؛ عنوان API في وضع `ui-test` يشير إلى localhost وتتم محاكاة كل نداء API.

## 2. المتطلبات التي لا تزال بحاجة لاختبار قبول متصل
| حالة الفحص | الحالة | ملاحظات |
| --- | --- | --- |
| بناء TypeScript/Vite واختبار العقود | تحقق منها CI | التنفيذ عبر GitHub Actions |
| حساب مسؤول تجريبي في متصفح مع مصادر اصطناعية | مؤتمت | لا تُستخدم بيانات المستخدم الحقيقية |
| حساب موظف محدود الصلاحيات | مؤتمت | إخفاء وحدات غير مصرح بها |
| حساب بلا صلاحية تقرير | مؤتمت | منع فتح التقرير |
| الفشل الجزئي لأحد مصادر البيانات | مؤتمت | يظهر «غير متاح» لا صفرًا |
| إخراج Excel والتحقق من `PowerBI_Data` | مؤتمت | استيراد `xlsx` وفحص أسماء الأوراق والمقاييس |
| PDF عبر محرك المتصفح | مؤتمت | فحص أن الملف صالح وله صفحات |
| التحقق البصري اليدوي من الطباعة العربية | لم ينفذ على بيئة اختبار متصلة | يلزم معاينة خطوط RTL والهوامش بالأحجام المختلفة |
| صلاحيات الخادم ونتائج بيانات حقيقية بمستخدمين فعليين | لم تنفذ | يلزم بيئة staging متصلة ومصرح بها |
| فحص الحد الأقصى ١٬٠٠٠ سجل للأراضي | لم ينفذ على بيانات فعلية | واجهة الخدمة الحالية قد تُرجع جزءًا من السجلات |
| ربط مباشر مع Power BI | غير مفعل | يحتاج اعتمادًا تقنيًا وأمنيًا مستقلًا |

## 3. حالة Railway عند الفحص (20 نوفمبر 2026)
- المشروع المسمى `intuitive-comfort` يتضمن بيئة `production` للواجهة والخلفية `iau-deeds-frontend` و`iau-deeds-backend`.
- البيئة `iau-deeds-restore-test` المتاحة لا تتضمن في جرد خدماتها واجهة أو Backend للتقرير، بل خدمة PostgreSQL فقط.
- لذلك **لم يُجرَ نشر التقرير على staging، ولم يُربط أي متصفح اختبارات ببيانات الإنتاج**.
- لم يتغير إعداد النشر أو متغيرات الخدمات أو اتصال PostgreSQL، وبقي طلب الدمج #155 في حالة Draft.

## 4. شروط اعتماد الدمج
1. جميع اختبارات CI على **آخر commit** ناجحة.
2. مطابقة أرقام التقرير الفعلية مع السجل المركزي والصكوك والأراضي والمعاينات والمتابعة.
3. تجربة حساب مسؤول وحساب موظف محدود الصلاحيات على بيئة اختبار متصلة لا تُستخدم فيها حسابات الإنتاج أو كلمات مرور حقيقية في CI.
4. مراجعة مطبوعة PDF وتصدير Excel عربي مع التأكد من عدم تسرب بيانات أو صيَغ Excel غير مأمونة.
5. موافقة المسؤول على دمج PR #155 ثم نشره؛ لا يُنفّذ الدمج أو نشر إنتاجي تلقائيًا.
