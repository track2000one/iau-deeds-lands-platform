# خطة جاهزية الربط مع Power BI — منصة IAU-DEEDS

> الحالة: **تم تجهيز تصدير لقطة مجمّعة من التقارير التنفيذية فقط**. لا يوجد اتصال تلقائي أو حساب خدمة أو صلاحية وصول مباشرة إلى PostgreSQL ضمن هذا التطوير. لا تُنشر قواعد بيانات الجامعة أو بيانات الدخول في الشيفرة.

## نطاق ما تم تطويره

- صفحة `/#/reports/executive` متاحة فقط لحساب يملك `reports.canView`، بينما أزرار التصدير والطباعة تتطلب `reports.canPrint` أو مسؤول النظام.
- بيانات كل وحدة تُحمّل من مسارات API الموجودة مسبقًا مع بقاء التحقق من الصلاحيات على الخادم.
- تصدير Excel يضم `Executive_Summary` و`Campus_Distribution` و`PowerBI_Data`.
- يُحتفظ بمفتاح مؤشر ثابت (`metric_key`) مستقل عن ترجمة عنوانه، مع مصدره وتاريخ لقطة البيانات والمرشحات وحالة الجودة.
- لا تُضاف بيانات موظفين أو مرفقات أو أرقام هويات أو كلمات مرور إلى ملف التصدير.
- تحذير صريح عندما تبلغ قائمة الأراضي الشاغرة سقف خدمة API الحالي (١٬٠٠٠ سجل).

## عقد بيانات `PowerBI_Data` (حقل لكل صف)

| العمود | المعنى | مثال |
| --- | --- | --- |
| `snapshot_utc` | وقت جمع بيانات المصادر بتوقيت UTC | `2026-11-20T18:00:00.000Z` |
| `metric_key` | معرف ثابت للمؤشر | `buildings.linked` |
| `module` | الوحدة مصدر المؤشر | `central_buildings` |
| `metric_label` | مسمى عرض محلي | `مبانٍ مرتبطة بصك` |
| `value` | القيمة الرقمية | `12` |
| `unit` | نوع الوحدة | `count`, `sqm`, `percent` |
| `campus_filter` | الحرم المختار للمباني/الأراضي الشاغرة، وإلا فارغ | `الحرم الشرقي` |
| `period_days` | نطاق تاريخ الصكوك والمعاينات؛ فارغ إذا جميع الفترات | `90` |
| `data_scope` | يوضح أن اللقطة ضمن صلاحيات الحساب | `authorized_module_scope` |
| `quality_status` | جودة المصدر | `REPORTED` / `POTENTIALLY_PARTIAL` |

**قواعد التفسير:**
1. مجموع السجلات عبر الوحدات لا يمثل عدد عقارات فريدة؛ لا يجوز جمع عدد المباني مع الصكوك بوصفه أصلًا موحّدًا.
2. `buildings.total` يحسب السجل المركزي فقط، ولا يضيف المباني المؤجرة أو المصليات.
3. `deeds.area_sqm` هو مجموع المساحات المسجلة وليس المساحة المساحية المعتمدة أو المساحة المستثمرة.
4. `vacant.approximate_sqm` يختلف عن `vacant.verified_sqm` ولا يجوز دمجهما.
5. مؤشرات المعاملات تأتي من ملخص المتابعة وفق نطاق صلاحيات المستخدم. لا تضاف سجلات مؤرشفة إلى الملخص الحالي.
6. الحرم يرشّح فقط المباني والأراضي الشاغرة، والمدة ترشّح فقط إنشاء الصكوك وزيارات المعاينات. بقية المؤشرات غير مشمولة بمرشحات التاريخ أو الموقع.
7. إذا لم يتوفر المصدر فلا يُنشر مؤشر بقيمة صفر. يجب التفريق بين `UNAVAILABLE` و`0` قبل أي دمج مؤسسي.

## تصميم التكامل الآلي اللاحق (يتطلب اعتمادًا منفصلًا)

1. **المصدر المفضل**: إنشاء `BI read model` على الخادم أو مشاهد PostgreSQL مخصصة للقراءة فقط، مع قواعد موحدة لتعريف العقار الفريد وربط المبنى بالصك والأرض. لا تعرض API العامة الخام مباشرة.
2. **هوية الخدمة**: اعتماد حساب قراءة فقط ومبدأ الحد الأدنى من الامتيازات، وإدارة بيانات الاعتماد في خزنة أسرار، وليس في React أو مستودعات GitHub.
3. **العزل**: يُفضّل نسخة قراءة أو مصدر تحليلي منفصل عن العمليات المباشرة للإنتاج. يتم اختبار الأداء ووقت الاستعلام وقيود الشبكة قبل اختيار Import أو DirectQuery.
4. **البيانات والصلاحيات**: تعيين تصنيف السرية، وربط قنوات النشر بصلاحيات منصة Microsoft، وتطبيق Row-Level Security واختباره فعليًا على الأدوار المعنية.
5. **التحديث**: تحديد جدول تحديث وتصحيح التوقيت، والتحقق من الحاجة إلى Data Gateway بحسب إمكانية وصول خدمة Power BI إلى قاعدة البيانات وبنية الاتصال المختارة.
6. **الاختبارات**: مطابقة أرقام Power BI مع مصدرها في IAU-DEEDS لحالات (حرم محدد، صلاحيات محدودة، بيانات غير متاحة، أراضٍ تتجاوز حد العرض، معاملتان متطابقتان، مبنى مشترك الاسم بصك مختلف).
7. **الاعتماد**: لا تفعيل لربط قاعدة الإنتاج أو مشاركة تقرير مؤسسي قبل موافقة الجهة المعنية وأمن المعلومات واستكمال فحص الصلاحيات.
